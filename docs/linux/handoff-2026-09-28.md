## ZIP 内容及恢复方法

本包采用项目根目录相对路径，包括：

- 本交接文档和 `docs/hardware/bringup-review.md`（早期分析，仅作参考）。

- `openstlinux/sources/ostl-linux/tf-a-stm32mp-v2.10.24-stm32mp-r3.1-r0/`：TF-A 开发包及已经应用 ST 补丁的源码快照。保留原始 tar.xz、补丁、README、Makefile 和 fiptool。
- `TRANSFER-MANIFEST.sha256`：以上各文件的 SHA-256 校验清单。

另一台电脑已有完整 Git 仓库及厂家资料/硬件文档，因此 ZIP 不含 `.git`、`docs/ATK/`、硬件 PDF/Excel、SDK 安装目录或完整 OpenSTLinux SOURCES 包。不要把本 ZIP 当作可烧录镜像。

先解压到独立临时目录，检查清单，再将相对目录合并到另一台电脑的项目根目录：

```bash
unzip /实际路径/DDG-STM32MP257-learning-handoff-2026-09-28.zip -d /tmp/ddg-handoff-20260928
cd /tmp/ddg-handoff-20260928
sha256sum -c TRANSFER-MANIFEST.sha256
```

恢复时注意：

1. `boards/`、`docs/`、`build/`、`openstlinux/` 都应位于现有仓库根目录下，不要多套一层项目目录。
2. 若目标文件不存在，直接复制相应目录；若已有同名文件，先比较内容并保留目标机的本地修改，不要整批强制覆盖。
3. TF-A 源码快照已经应用 ST 补丁，不要再次 `patch`、`git am`，也不要在其上重新解压原始 tar.xz。
4. 若另一台机器已有同版本且已打补丁的 TF-A，可先比较后保留它；不要用旧版本 TF-A 混合本次设备树。
5. SDK 不可通过复制本机安装目录迁移。目标机若尚未安装，按 `docs/setup.md` 安装相同版本到目标机的实际路径。当前 SDK 为 x86_64 Linux 主机版本。
6. 顶层 Git 忽略 `openstlinux/` 和 `build/`，复制完成不意味着这些内容会随 Git 提交同步。没有建立 TF-A 内层 Git 仓库。板级源码放 `boards/`，未来第三方改动用 `patches/` 保存。
7. 预处理/DTB 产物只是当前语法检查快照，未来修改源码后必须重新生成。
8. `rg` 搜索整个被忽略的源码目录时应加 `--no-ignore`；此前不加此选项导致错误判断串口节点不存在。

## 当前板级配置与验证结果

`stm32mp257d-ddg-pinctrl.dtsi`：在 `&pinctrl` 下声明两线 USART1 引脚组，标签 `ddg_usart1_pins`。TX 推挽、slew-rate=0，两脚关闭内部上下拉。

`stm32mp257d-ddg.dts`：设置 model/compatible、serial0=&usart1、stdout-path=serial0:115200n8，启用 USART1 并引用引脚组；声明 HSI 64MHz，配置 FLEXGEN19 使用 HSI、不分频。

推导来源：

- `fdts/stm32mp251.dtsi` 的 `usart1: serial@40330000`，时钟引用 `CK_KER_USART1`。
- `drivers/st/clk/clk-stm32mp2.c`：STM32MP25 USART1 → FLEXGEN19；MP21 分支是 18，不能混淆。
- `include/dt-bindings/clock/stm32mp25-clksrc.h`：`FLEXGEN_CFG` 编码和时钟源宏。
- `clk_flexgen_recalc()`：输出频率为输入 / (prediv+1) / (findiv+1)，0/0 表示不分频。
- 本地 RM0457 第 21 章 RCC 可用于交叉核对硬件定义。`clock-frequency` 是软件使用的频率描述，单独写这个属性不等于初始化整棵时钟树。

用户已经亲自完成：

1. 预处理生成 `stm32mp257d-ddg.pre.dts`。
2. dtc 生成 `stm32mp257d-ddg.dtb`，`dtc.log` 为空。
3. 反编译生成 `stm32mp257d-ddg.decoded.dts`。

助手已读取结果：USART1 `status="okay"`，`pinctrl-0` 引用 phandle 3；PG14/PG15 编码为 0x6e07/0x6f07；serial0 指向 `/soc@0/rifsc@42080000/serial@40330000`；HSI 属性 64000000。

时钟属性反编译显示为 `st,flexgen = "\r8\0"`，属于 dtc 对属性字节显示类型的猜测，不代表其已变成错误配置。下一步是用 fdtget 明确按整数读取。上一轮已给命令，但用户没有报告执行结果，交接时不要宣称该项已验证。

当前只验证了设备树语法及引用，未使用完整 TF-A 构建规则（例如 BL2 附加设备树/裁剪），没有生成可运行 TF-A、FIP、完整 `.img`，没有刷写或上板验证。RCC、PMIC、DDR、内存等配置尚不完整；早期控制台可能有独立初始化路径，不能保证只改 stdout-path 即可获得所有阶段日志。

## 换机后恢复环境与检查命令

在新机器项目根目录、同一个 Bash 终端执行。路径由当前目录计算，不沿用旧机器绝对路径：

```bash
source openstlinux/sdk-installed/environment-setup-cortexa35-ostl-linux
TFA_SRC="$PWD/openstlinux/sources/ostl-linux/tf-a-stm32mp-v2.10.24-stm32mp-r3.1-r0/tf-a-stm32mp-v2.10.24-stm32mp-r3.1"
BOARD_DIR="$PWD/boards/ddg-stm32mp257/tf-a"
CHECK_DIR="$PWD/build/ddg-stm32mp257/dt-check"

# 当前应接着做的只读检查，预期输出 d380000
fdtget -t x "$CHECK_DIR/stm32mp257d-ddg.dtb" \
    /soc@0/clock-controller@44200000 st,flexgen
```

需要重做语法检查时，由用户执行以下命令；某一步失败就先停止，避免误看旧 DTB：

```bash
mkdir -p "$CHECK_DIR"
$CC -E -P -x assembler-with-cpp -nostdinc -undef \
    -D__DTS__ \
    -I "$TFA_SRC/include" -I "$TFA_SRC/fdts" -I "$BOARD_DIR" \
    "$BOARD_DIR/stm32mp257d-ddg.dts" \
    -o "$CHECK_DIR/stm32mp257d-ddg.pre.dts"

dtc -I dts -O dtb \
    -o "$CHECK_DIR/stm32mp257d-ddg.dtb" \
    "$CHECK_DIR/stm32mp257d-ddg.pre.dts" 2> "$CHECK_DIR/dtc.log"

dtc -I dtb -O dts \
    -o "$CHECK_DIR/stm32mp257d-ddg.decoded.dts" \
    "$CHECK_DIR/stm32mp257d-ddg.dtb"
```
